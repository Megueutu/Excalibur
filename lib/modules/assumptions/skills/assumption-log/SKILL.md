# Assumption log

An assumption is anything you decided to treat as true without checking it with the person who asked.

## While working

Keep a short running list. Add an item the moment you assume, in one sentence each:

- what you assumed,
- what it was based on (the request, the project, a convention),
- how to tell if it was wrong.

## When the task ends

Close with the list, in the user's own language and level of detail. Put the likeliest-to-matter items first. For each, say what changes if the assumption was wrong.

If the task has a folder in the SDD, also keep the list there as an `Assumptions` section of its log, so it outlives the conversation.

## Rules

- Do not ask about an item just because it is on the list. The list exists so you can proceed and still be accountable.
- If an assumption would be expensive to get wrong or impossible to undo, it is not an assumption to make alone. Follow the pause rules instead.
- Never record a secret, a credential or personal data.
